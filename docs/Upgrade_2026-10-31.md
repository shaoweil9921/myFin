## How to Ensure Connection After Upgrade

### Session Isolation (Current Session is Safe)
- This session runs in the **already-loaded process** — it is NOT affected by the package upgrade
- Only **new sessions** after restart would be impacted if the new binary is broken
- Current session stays alive on the old binary until it exits naturally

### Verification Plan
1. **After upgrade + restart** → `openclaw status` and `openclaw gateway status`
2. **Test a new session** → open a new browser tab / send a test message
3. **Check Control UI** → http://localhost:18789 → version footer should show 2026.10.9
4. **This session** → confirm it still responds normally after gateway restart
5. **Discord pipeline** → `openclaw cron runs e1e338d4-3dc8-4ade-b570-5e92ecf8c14c` → last run `ok`

### If Something Breaks
```powershell
# Option A: manual restore from the pre-upgrade backup
#   gateway MUST be stopped first — restoring a live SQLite file corrupts it
Copy-Item C:\Users\shaowei_l\.openclaw\backup\2026-10-31_pre-upgrade\openclaw.json `
          C:\Users\shaowei_l\.openclaw\openclaw.json -Force
Copy-Item C:\Users\shaowei_l\.openclaw\backup\2026-10-31_pre-upgrade\openclaw.sqlite `
          C:\Users\shaowei_l\.openclaw\state\openclaw.sqlite -Force
Copy-Item C:\Users\shaowei_l\.openclaw\backup\2026-10-31_pre-upgrade\openclaw-agent.sqlite `
          C:\Users\shaowei_l\.openclaw\agents\main\agent\openclaw-agent.sqlite -Force
#   then restart via the gateway-aware path

# Option B: revert to old version
npm i -g openclaw@2026.9.9 --no-fund --no-audit
```
